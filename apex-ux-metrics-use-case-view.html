03

Where the mapping still leaks

6 findings from the CSV

Every item below is visible in the CSV as it stands, before any traffic is joined. They are cheap to fix now and expensive to discover in a published number.

Blocking · prefix

One path is the parent of another, across two use cases

NII/irrbb/exercise-management
CSAT/irrbb/exercise-management/bsp

Under prefix matching, every CSAT page view also counts as NII. Both use cases end up wrong, in opposite directions, and neither number looks broken.

FixDeclare one rule — exact match, or longest prefix wins — and apply it everywhere.
Blocking · naming

“Manual update” and “Manual upload” are different tasks

NII/manual-update/irrbb
Submission/manual-upload/submission-portal

The current report carries a workflow context called Manual Upload. Joined to the wrong route, an assumption refresh and a submission become the same thing.

FixPin the join key before the first metric is computed.
Structural · shared container

Superset reports are named one by one, so the container is unattributed

Mortgage/superset-report/mp-… (×2)
Rapid dev/superset-report/sh-…

Every new Superset report ships with no use case until someone edits the CSV — the exact “it will go stale” failure the automated site map is meant to catch.

FixAdd a catch-all row /superset-report/* that reports its own unmapped share.
Blocking · duplicate

Two spellings of one page

Deposit/deposit/report
Deposit/deposit/reports

Harmless for use case attribution, since both belong to the same task. Fatal for route-level error counting: one page’s failures split across two rows and neither looks severe.

FixConfirm the live route, delete the other.
Minor · case

The only capitalised path in the file

Mortgage/MortgageProductPipeline

Case-sensitive matching drops it with no error, which reads as zero traffic rather than as a bug.

FixNormalise to lower case on match.
Minor · no event

Three “use cases” are places, not tasks

Nav/  ·  /home
Other/products · /about · /apex-support

Keep them in the map, exclude them from reach and from task success — otherwise browsing fills the denominator and every success rate drops without anything getting worse.

FixFlag them non_task = true.

05

What the mapping cannot answer yet

4 columns to add

The CSV gives attribution — which use case a page belongs to. It does not give progression — where in the task the user stopped. Task success and error rate need both.

Add to the CSVTypeExample (NII)What it unlocks
entry_route required /irrbb/assumption-management Defines where the task starts. This is the denominator.
completion_event required /calculation/nii returns a result Defines success. This is the numerator.
match_rule enum longest-prefix One rule applied everywhere kills the whole conflict class in §03.
owner string NII use case owner Moves action ownership off “UX + Data” and onto someone who can close it.

With the first two columns, task success and error rate stop being not measurable yet and become arithmetic. That is the whole of the denominator problem on the Actions page.
